# 기능 확장 개요

## 목표·확정 범위

빠른 입력을 유지하며 구성원/공용 귀속·소분류·결제 수단을 저장하고 달력/목록/상세, 월 예산 승계·배분, 통계를 확장한다. 제목 입력은 추가하지 않고 카테고리·소분류 아래에 메모를 표시한다. 구성원·귀속, 소분류, 사용자 이름은 완료했고 결정은 PRODUCT.md·DESIGN.md·ARCHITECTURE.md에 반영했다. 나머지는 계획 단계다.

- 보기: 월 이동·지출/수입 → 예산 설정 → 목록/달력 전환 → 해당 보기. 날짜 → 일별 내역 → 기록 상세.
- 예산: 총예산을 설정하고 그 안에서 일부 카테고리만 배분할 수 있다. 변경한 금액·배분을 이후 달에 적용하고 이전 월은 보존한다.
- 결제 수단: 지출만 체크카드·신용카드·현금. 기본값은 설정에서 고르며 최초 체크카드, 미지정도 허용한다. 통계 지표는 추후 결정한다.

## 데이터 설계 진입 조건

확정한 제품 선택을 CHECK/nullability·기존 데이터 migration에 반영한다. 남은 사항은 해당 migration 전에 정한다.

1. 결제 수단 결정은 [결제 수단 계획](profile-payment.md)에 둔다.
2. 확정: 전체 예산 안에서 일부 배분 가능, 배분 합계는 전체를 초과하지 않는다.
3. 예산 자동 승계 시작 월과 초기 기준값. 출시 전 과거 누락분을 추정하지 않는다.
4. 카테고리는 가계부별 자유 편집·삭제/미분류 이동, 2단계 소분류로 정했다. 예산 배분을 추가할 때 삭제 RPC와 FK를 함께 확장한다. 그 밖의 계정 삭제·이름 제약·정렬·성능 검토는 [DB 후속 결정](database-followups.md)에 둔다.

## 주요 설계안·구현 순서

아래 순서로 구현한다. 각 항목의 적용·검증 상태는 개별 계획에서 구분한다.

1. [결제 수단](profile-payment.md): 지출 결제 수단과 설정의 기본값.
2. [달력·목록·상세](record-views.md): 기존 내역 탭을 확장. 별도 기록 탭을 추가하지 않는 안.
3. [월 예산](monthly-budget-inheritance.md): 설정 월/경계 월만 저장, 조회 시 직전 유효 설정 묶음 승계.
4. [통계](statistics.md): 위 데이터 관계가 안정된 뒤 지표·화면 결정.

## 검증·문서 정리

각 코드 변경 후 flutter analyze와 flutter test를 실행한다. 금액·날짜·월 합계·예산·가계부 접근 회귀를 확인하고, Fake/HTTP와 실제 OAuth·DB/RLS·브라우저 검증을 구분한다.

각 기능 완료 시 해당 계획의 결정을 PRODUCT.md·DESIGN.md·ARCHITECTURE.md에 반영하고 그 계획을 삭제한다. 개요에는 남은 범위만 유지한다. 현재/예정 기능은 제품·디자인 문서에서 구분한다.
