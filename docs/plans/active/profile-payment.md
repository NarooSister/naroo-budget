# 사용자 이름·결제 수단

## 목표·범위

이름 설정과 결제 수단은 각각 독립 변경으로 구현한다. 첫 로그인에서 이름을 설정하고 설정에서 변경한다. 지출에는 체크카드·신용카드·현금을 기록한다. Household 문구 교체는 별도 작은 수정으로 처리한다.

## 주요 결정·진입 조건

- profiles에 사용자가 이름을 확인한 시각/상태를 별도로 추가한다. 기존 Google 이름만으로 설정 완료를 판정하지 않는다. 기존 사용자도 한 번 확인하고 이후 로그인에서 사용자 이름을 덮어쓰지 않는다.
- 입력 제한 제안: 앞뒤 공백을 제거한 이름 1~30자, 빈 값/공백만 입력 거부. UI/DB에서 같은 문자 수 기준을 사용하고 migration 전에 확정한다. 설정 완료 상태와 유효 이름의 관계도 제약으로 검증한다.
- 프로필과 계정에 연결된 본인 구성원 이름을 서버에서 원자적으로 동기화한다. 임의 구성원은 제외하고 user_id/소속은 변경하지 않는다. 구성원 연결 전 이름 저장도 지원한다.
- profiles는 로그인 계정 이름의 원본, household_members는 가계부 귀속·표시용이다. 로그인 구성원 이름 복제는 위 저장 경로에서 동기화하며 직접 프로필 쓰기로 우회하지 못하게 한다. 동기화 전에 기존 이름 차이를 확인하고 임의 추정으로 덮어쓰지 않는다. 구성원 이름은 과거 거래 당시의 스냅샷이 아니다.
- 확정: 새 지출도 결제 수단 미지정 허용. 기존 기록도 미지정으로 보존하며 방법을 추정하지 않는다. nullable 필드 + 허용 세 값 CHECK를 사용한다. 수입 미적용·자동 선택 기본값은 제안으로 두고 migration 전에 확정한다.
- 개별 카드·청구일·할부·계좌 잔액은 포함하지 않는다. 신용카드도 occurred_on 기준으로 지출을 한 번만 합산한다.

## 검증 기준

- 신규/기존 이름 확인, 재로그인 유지, 연결 전후 세션, 이름 제한·실패 복구, 설정/구성원/거래 표시 갱신, 본인 외 변경 차단.
- 세 결제 수단의 생성·수정·상세, 기존 미지정 호환, 확정한 수입/필수 제약, 금액 합계 회귀.
- 이름·결제 수단 각각 완료 시 관련 PRODUCT.md·DESIGN.md·ARCHITECTURE.md만 갱신하고 완료 항목을 제거한다.
