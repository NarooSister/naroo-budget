# 선택 소분류

## 목표·범위

식비 → 장보기/외식처럼 2단계 분류를 설정에서 관리한다. 소분류는 선택 사항이며 금액 → 카테고리 → 저장 경로를 유지한다. 제목은 추가하지 않는다.

## 주요 결정

- 최소 변경 우선안: categories.parent_id nullable 추가. transactions.category_id는 대분류를 유지하고 nullable subcategory_id만 추가한다.
- 부모는 같은 가계부·같은 수입/지출 유형의 대분류만 허용한다. 자기 참조·순환·3단계·거래의 대분류 불일치를 DB에서 차단한다. 부모/유형 변경 시 기존 거래 참조가 깨지는 변경도 차단한다.
- 기존 category_id·메모는 보존하고 기존 subcategory_id는 null이다. 기존 월 합계·대분류 예산 집계를 유지하며 소분류는 필터/세부 집계용으로 사용한다.
- 목록/상세는 ‘식비 · 장보기’, 아래 메모를 표시한다. 대분류나 거래 유형 변경 시 맞지 않는 소분류 선택을 해제한다.
- 카테고리 숨김은 사용하지 않는다. 삭제는 기존 `delete_category` RPC를 확장한다. 대분류 삭제 시 자식 처리, 소분류만 삭제할 때 대분류 유지/미분류 이동 규칙은 구현 전에 확정한다. 거래의 category_id/subcategory_id를 한 트랜잭션에서 정리하고 FK로 고아 참조를 막는다. 미분류는 대분류로 유지하며 자식 생성 허용 여부를 결정한다. 부모 이동은 초기 범위에 포함하지 않는다.

## 검증 기준

- 기존 거래·합계 호환, 소분류 없이 저장, 추가·수정·삭제/미분류 이동, 부모 변경 시 선택 초기화.
- 다른 가계부·유형·부모 연결, 3단계 및 기존 참조를 깨는 분류 변경 차단. 부모/자식 집계 중복 없음.
- 완료 시 분류 규칙을 PRODUCT.md·ARCHITECTURE.md에 반영하고 이 계획을 삭제한다.
